# Установка — Claude OS Kits

Любой кит стоит на **Core-Lite**. Core-Lite ставится один раз; установка второго кита —
это добавление модуля, а не переустановка.

## Требования

- Python 3.8+ (`python3 --version`). Сторонние пакеты не нужны.
- Папка проекта. Может быть пустой или уже существующим репозиторием.
- Claude Code или Cowork — основная платформа. Cursor и generic `AGENTS.md` — через адаптеры.

## 0 · Распаковать и зайти в папку кита

```bash
unzip claude-os-kits-all-1.3.0-source.zip
cd claude_os_kits
```

**Все команды ниже выполняются изнутри `claude_os_kits/`, а не оттуда, куда ты распаковал.**
Инсталлятор определяет корень кита по собственному расположению, поэтому
`python3 core/install/install.py` находит себя только если этот путь существует относительно
текущей папки. Пропустить `cd` — получить `can't open file '.../core/install/install.py'`.
Это самый частый отказ на первой минуте, поэтому шаг теперь записан явно.

## 1 · Preflight

Сначала пройди `preflight_check.md`. Две минуты, и они закрывают три самые частые причины
сломанной установки.

## 2 · Пробный прогон

Не ставь вслепую. Сначала спроси, что произойдёт:

```bash
python3 core/install/install.py --target /путь/к/проекту --kit all --dry-run
```

Прочитай список. Каждая строка — файл, который появится в проекте.

## 3 · Установка

```bash
python3 core/install/install.py --target /путь/к/проекту --kit all
```

Инсталлятор спросит значения плейсхолдеров. Enter — оставить значение по умолчанию.

| Плейсхолдер | Что это | Пример |
|---|---|---|
| `PROJECT_NAME` | Как Клод называет проект | `Acme Docs` |
| `VAULT_PATH` | Абсолютный путь к корню проекта | `/Users/you/acme` |
| `LANG` | Язык ответов в чате | `en`, `ru`, `ua` |
| `DOMAIN_LIST` | Рабочие домены | `research, support, engineering` |
| `OPUS_GATE_%` | Потолок прогонов на топ-модели | `10%` |

Ответы сохраняются в `claude_os.config.json` в корне проекта. Повторный запуск читает этот файл —
поэтому ничего не спрашивает второй раз и рендерит ровно тот же результат.

Поставить один кит:

```bash
python3 core/install/install.py --target /путь/к/проекту --kit kit3_research
```

Core-Lite добавится сам — это жёсткая зависимость.

## 3.5 · Ответить на вопросы — когда системе работать

Инсталлятор спрашивает это один раз, интерактивно, и кладёт ответы в `claude_os.config.json`,
ключ `review`. Их читает `.claude/rules/review_policy.md`; политика нигде не зашита в код, потому
что нужная глубина проверок зависит от того, чем вы реально занимаетесь.

Что спрашивает:

| Вопрос | Почему это важно |
|---|---|
| Какие работы получают **изолированный verifier** до сдачи? | Это дорогая проверка. Клиентские деливераблы, правки always-load правил и агентов, необратимое, выводы, на которые будут ссылаться. Запускать на всём — и его перестают слушать. |
| Какие работы не получают **ни одной** проверки? | Быстрые факты, рутина, черновики для себя, обычный чат. Доказывать нечего — и платить не за что. |
| Оценивать готовое **судьёй**: каждый прогон или выборку? | Дёшево, работает после сдачи. `all` во время активной разработки, `sample` в спокойный период. |
| Нужен ли недельный **retro**, в какой день и час? | Собирает предложения по улучшению пачкой — вы принимаете или отклоняете. |

Два момента:

- **Инсталлятор никогда не создаёт запланированную задачу.** Если попросить недельный retro, он
  напечатает строку cron и запишет `scheduled_task_created: false`. Ставить расписание — ваше
  решение, а не инсталлятора.
- **Вопросы появляются только на настоящем терминале.** Установка из скрипта, по пайпу, в CI и
  любой прогон с `--yes` молча берут значения по умолчанию. Если ставите скриптом — поправьте
  `claude_os.config.json` после или перегоните инсталлятор интерактивно.

Ответы переживают переустановку — второй прогон их не сбрасывает.

## 4 · Что куда ложится

Установка всех трёх китов кладёт 83 файла. Верхний уровень целиком:

```
твой-проект/
  CLAUDE.md                  # управляемый блок вмерживается; твой текст не трогается
  claude_os.config.json      # твои значения плейсхолдеров
  .claude/
    rules/                   # naming, writing_style, model_routing + все правила китов (12)
    agents/                  # install_verifier + агенты китов (7)
    skills/                  # скиллы китов, каждый — отдельная папка (8)
    hooks/                   # Reliability Kit: скрипты хуков + сниппет, который сливаешь сам
    adapters/                # claude_plugin, cursor_sync, agents_md_export
    install/                 # uninstall.py — чтобы удаление работало после удаления папки кита
  memory/                    # Reliability + Growth: решения, выводы, буферы, журнал изменений
  scripts/                   # Growth Kit: judge, dashboard_lite, cost, security
                             # Research Kit: embeddings_search (опционально)
  docs/
    reliability_kit/         # README, QUICKSTART ru+en, FAQ, demo_scenarios
    growth_kit/              # README, QUICKSTART ru+en, FAQ, safety_note
    research_kit/            # README, QUICKSTART ru+en, FAQ
  templates/                 # cost_card, report_exec_summary
  _moc.md                    # только Research Kit: точка входа vault-lite
  00-capture/  10-reference/  30-reports/     # только Research Kit: скелет vault-lite
  .claude_os/installed.json  # что именно поставлено, с хэшами
```

Ставишь один кит — получаешь Core-Lite плюс строки только этого кита, остального не появится.

## 5 · Зарегистрировать хуки — только Reliability Kit и только Claude Code CLI

**Пропустишь — следующий шаг выдаст FAIL.** Инсталлятор копирует скрипты хуков, но никогда не
правит твой `.claude/settings.json`: тихо переписывать файл настроек, который принадлежит тебе,
инсталлятор не должен. Поэтому регистрация — один ручной шаг:

1. Открой `.claude/hooks/settings.snippet.json`.
2. Влей его блок `hooks` в `.claude/settings.json`. Если этого файла ещё нет — создай его с
   содержимым сниппета: инсталлятор намеренно его не создаёт.
3. Перезапусти сессию Claude Code и отредактируй любой файл. Намеренно битый `.py` должен дать
   сообщение. Пока не увидел срабатывание своими глазами — считай, что хук не работает.

Подробности и два copy-paste теста: `.claude/hooks/README.md`.

**Хуки срабатывают только в Claude Code CLI.** Cowork и Cursor не читают `.claude/settings.json`,
поэтому там этот шаг ничего не даёт, а те же гарантии держат правила протокола — см.
`.claude/hooks/cowork_protocol.md`. Это устройство продукта, а не сломанная установка.

## 6 · Проверка

Открой свежую сессию Клода в проекте и вставь:

```
Read .claude/agents/install_verifier.md and follow it.
```

Он прогонит smoke-тест по манифесту и выдаст PASS/FAIL по каждому пункту. Сделай это до того,
как начнёшь полагаться на установку: файл, который тихо не скопировался, выглядит точно так же,
как рабочая система — до дня, когда он понадобится.

## 7 · Повторный запуск безопасен

```bash
python3 core/install/install.py --target /путь/к/проекту --kit all
```

Второй прогон печатает `TOTAL: 0 written` и ничего не меняет. Файлы, которые ты правил после
установки, определяются по хэшу и пропускаются, а не перезаписываются. `--force` — только если
ты осознанно хочешь стереть свои правки.

## Обновление

Скачай новую версию кита и запусти инсталлятор снова. Перезапишутся только реально изменившиеся
файлы; твои локальные правки защищены той же проверкой по хэшу.

## Удаление

См. `uninstall.md`.

## Официальные скиллы Anthropic

Киты не перепаковывают скиллы Anthropic (`docx`, `pdf`, `pptx`, `xlsx`, `deep-research`).
Где кит на такой скилл рассчитывает — в его README стоит ссылка на официальную установку.
Ставь их отдельно.
